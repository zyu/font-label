# 开发任务拆解与排期

> 阅读顺序：先读 `01-产品需求文档.md`（规则），再读 `02-技术方案与数据设计.md`（怎么实现），开发时对照 `03-验收标准与测试用例.md` 自测。
> 说明：每个任务都必须"改完即能跑"，不允许留 TODO 占位。

## 1. 分工建议

| 角色 | 主责 | 主要产出 |
| --- | --- | --- |
| 后端 1 人 | 数据库、鉴权、上传、领取、导出、部署 | `server/` |
| 前端 1 人 | 工作台、审核页、统计、管理页 | `web/` |
| 联调 | 双方共用 `api/openapi.yaml` 契约 | 契约先定，后并行 |

若 1 人全栈：按 M0→M6 顺序做，每个里程碑结束跑一次验收子集。

## 3. 依赖关系（并行提示）

```
M0 ─┬─ M1 ─┬─ M2 ─┬─ M3 ─┬─ M4 ─┬─ M5 ─┬─ M6
    └──────┴──────┴──────┴──────┴──────┘
契约(openapi.yaml) 必须在 M0 结束前定稿，之后前后端并行
```

- 前端可在 M1 后端接口未完成时用 mock（`msw` 或 vite proxy 到 stub），但 **M3 开始必须连真接口**。
- M5 统计接口依赖 M3/M4 产生数据，建议 M4 一半时先造 200 条测试数据。

## 4. 关键接口先行清单（M0 结束前定稿）

| 接口 | 为什么先定 |
| --- | --- |
| `POST /auth/login`、`GET /auth/me` | 前端路由守卫依赖 |
| `POST /images/upload` | 返回结构复杂（逐条结果），前端要据此写上传页 |
| `POST /claims` | 队列/进度/持有上限字段决定工作台状态设计 |
| `GET /images/{id}` | 标注页一次性拿到 图 + 标注 + 审核历史 + 签名 URL |
| `POST /images/{id}/submit` | 幂等键、总分回传，前端乐观更新依赖 |
| `POST /images/{id}/review` | 通过/打回结构，审核页核心 |

## 7. 不做（首版明确排除，避免范围蔓延）

- 手机端标注（只保证桌面浏览器）
- 视频 / 多字整页标注（一图一字）
- 自动评分模型（AI 预打分）
- 多级审核（初审+终审）
- 班级/学生管理、家长端
- 图上批注（P1，仅预留数据结构）
- 图片 zip 打包导出（P1）
