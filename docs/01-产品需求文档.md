## 1. 一句话定义

管理员把学生硬笔书法作业照片上传到服务器，标注员按「张」或按「文件夹」领取任务，在「左图右标注」的工作台里对每个字按四个维度打分并写点评（不合格的图片上报异常），审核员逐条审核、可批注打回，系统沉淀全量统计并支持按文件夹/日期/人员导出标注结果。

## 2. 业务背景与要解决的问题

现状：学生写字作业以照片形式汇总，靠人工看片打分，存在三个硬问题：

1. **任务无归属**：谁在看哪张、看到哪一步没有记录，同一张图被两个人重复打分。
2. **质量无闭环**：打完分没人复核，评分口径漂移，错了也没有"打回重做"的机制。
3. **数据无沉淀**：结果散落在 Excel 和微信里，无法按批次（文件夹）交付，也无法统计每个人的工作量与驳回率。

本平台就是把这条流水线**线上化、可追溯、可统计、可导出**。

## 3. 角色与权限

| 角色 | 说明 | 能做 | 不能做 |
| --- | --- | --- | --- |
| 管理员 admin | 机构/教务运营人员，通常 1~2 人 | 用户管理、文件夹管理、上传图片、配置评分方案与异常原因、查看全量统计、导出、强制回收/改派任务 | — |
| 标注员 annotator | 评分执行人，人数最多 | 领取任务（按张/按文件夹）、标注打分、上报异常、查看自己被驳回的任务并重做、查看自己的统计 | 看别人的待标注图、审核、导出全量、进管理页 |
| 审核员 reviewer | 质检，可为标注员兼任（同一账号双角色，见 3.1） | 审核队列、通过/打回（必填批注）、查看全量统计（只读） | 上传、改用户、改评分方案 |

### 3.1 双角色

一个账号可以同时是「标注员 + 审核员」（`roles` 为数组时以最高权限渲染菜单），但**不能审核自己标注的图片**（后端强制校验 `annotator_id != reviewer_id`，返回 403）。管理员天然拥有审核权。

## 4. 核心业务流程图

### 4.1 主流程

```
[管理员] 建文件夹(可选,默认当天日期) → 上传图片
        ↓  服务器落盘: storage/<文件夹>/<YYYYMMDD>_<NNN>.<ext>
        ↓  入库: status = unassigned
[标注员] 工作台 → 按张领取 N 张 / 按文件夹领取该文件夹剩余全部
        ↓  事务内锁定 → status = assigned (annotator_id, claimed_at, lock_expires_at)
        ↓  ★ 此后其他标注员的领取池里再也看不到这些图（不可重复领取）
[标注员] 左图右标注 → 五维打分（各 20 分）+ 点评 → 提交
        ↓  status = submitted（待审核）
[审核员] 审核队列 → 看图/看标注 → 通过 or 打回(必填批注)
        ↓  通过 → approved（进入导出集）
        ↓  打回 → rejected（回到该标注员的「我的驳回」，不进入公共池）
[标注员] 我的驳回 → 修改后重新提交 → submitted（版本号 +1，历史留痕）
        ↓
[管理员] 统计看板 / 按文件夹·日期·人员导出 xlsx
```

### 4.2 异常分支

```
标注员发现图片不可评（倾斜>15°/失焦/过曝/含未打码姓名/遮挡）
   → 点「上报异常」→ 勾选原因(≥1) + 备注(可选) → 提交
   → status = submitted, kind = exception
审核员：异常成立 → approved，且标记为 excluded（不计分，单独计入"无效图"统计）
        异常不成立 → 打回，要求正常打分（批注说明原因）
```

### 4.3 任务生命周期状态机（图片级）

```
                领取(按张/按文件夹)
   unassigned ────────────────────→ assigned ──提交──→ submitted
       ↑                              │  │                │  │
       │ 超时回收/主动放弃/管理员回收  │  │                │  │
       └──────────────────────────────┘  │                │  │
                                          │                │  │
                                    提交(异常)             │  │
                                          ↓                │  │
                                       submitted ──────────┘  │
                                                              │
                            审核通过 ┌────────────────────────┤ 审核打回
                                     ↓                        ↓
                                 approved                   rejected
                              (kind=score 计分)          (归属不变,可续做)
                              (kind=exception → excluded)     │
                                                              └──→ assigned(续做) ──提交──→ submitted
```

状态枚举与语义（后端以此为准）：

| status | 中文 | 可执行操作 | 归属 |
| --- | --- | --- | --- |
| `unassigned` | 待领取 | 领取 | 公共池 |
| `assigned` | 已领取（未提交） | 提交 / 放弃 / 超时回收 | 某标注员 |
| `submitted` | 待审核 | 通过 / 打回 | 某标注员 |
| `approved` | 已通过 | 撤销审核（管理员，P1） | 某标注员 |
| `rejected` | 已打回 | 标注员续做（→assigned）/ 管理员改派 | 原标注员 |
| `excluded` | 无效图 | —（终态，可管理员撤销） | 原标注员 |

## 5. 功能需求

### FR-01 用户与登录

- 账号密码登录（用户名 + 密码），**首版不接短信/企微**（见 §11 待确认）。
- 密码强度：≥8 位，含字母+数字；后端 `argon2id` 哈希。
- 管理员可新建账号、停用/启用、重置密码、改角色。停用即时生效（token 失效）。
- 登录失败 5 次锁定 10 分钟（按用户名+IP）。
- 会话：JWT Access Token（12h，前端存内存），Refresh Token（7d，httpOnly Cookie）。登出/改密/停用使 `token_version +1`，旧 token 全失效。
- 首次部署 seed 一个管理员：`admin / 环境变量 ADMIN_INIT_PASSWORD`，首次登录强制改密。

### FR-02 文件夹管理

- 文件夹 = 一次交付批次，是「按文件夹领取」和「按文件夹导出」的单位。
- 创建：名称必填（≤64 字符，允许中文，禁止 `/ \ : * ? " < > |`），备注可选，重名拒绝。
- 默认文件夹：上传时若未选，自动使用**服务器当天日期** `YYYYMMDD`（如 `20261022`）作为名称，不存在则创建。
- 列表展示：名称 / 总张数 / 待领取 / 已领取 / 待审核 / 已通过 / 已打回 / 创建时间 / 创建人，带进度条。
- 归档：仅当文件夹内所有图片均已审核通过（approved）或确认无效（excluded）时允许归档；待领取、已领取、待审核、已打回均阻止归档。归档后不能上传新图，可取消归档恢复使用（有标注数据的文件夹禁止物理删除）。
- 改名：同步更新磁盘目录（后端 rename），失败则回滚。

### FR-03 上传图片（管理员）

**命名规则（核心，必须严格实现）**

- 落盘文件名 = `<服务器当天日期 YYYYMMDD>_<三位序号 NNN>.<原扩展名小写>`
  例：`20261022_001.png`、`20261022_002.jpg`
- 序号**按天全局自增**，每天从 `001` 开始，跨文件夹连续（避免不同文件夹同天撞名）。
- 物理路径：`storage/<文件夹名>/20261022_001.png`；数据库同时记录 `stored_name`、`rel_path`、`orig_name`。
- 原文件名保留在 `orig_name` 字段，导出时可选择输出（默认输出服务器文件名 + 原文件名两列）。
- 序号分配必须**原子**（数据库 `daily_counters` 行锁 / `UPDATE ... RETURNING`），多管理员并传不得重号。
- 文件已存在同名视为异常，重试下一个序号（理论上不会发生，作为兜底）。

**上传交互**

- 支持：点击多选、拖拽多文件、拖拽整个文件夹（`webkitdirectory`，文件夹名自动作为目标文件夹名）。
- 单文件默认 ≤ 10MB（随系统配置显示和校验）；一次最多 200 个文件（可配置）；扩展名白名单 `jpg/jpeg/png/webp/heic/heif`。
- `heic/heif`（iPhone 默认格式）由服务端转码为 `jpg` 后落盘，`stored_name` 扩展名为 `.jpg`，`orig_name` 保留原 `.HEIC` 名称——避免标注员浏览器打不开。
- 服务端校验：扩展名 + MIME + 文件头魔数三重校验；非图片拒绝并逐条返回原因。
- **EXIF 处理**：按 EXIF Orientation 自动转正后**剥离全部 EXIF**（防 GPS/设备信息泄漏）；服务端记录 `width/height`。
- **重复检测**：同文件夹内 `sha256` 重复 → 跳过并提示「已存在同图（20261022_007）」，不覆盖。
- 上传结果逐条回显：成功 N 张 / 重复 M 张 / 失败 K 张（含原因），失败可「仅重试失败项」。
- 生成三档图：`original`（原图，最长边 ≤2400 自动降采样）、`preview`（1280px webp/jpg）、`thumb`（320px）。标注页加载 preview，缩略图列表用 thumb。
- 上传后图片状态 `unassigned`，立即可被领取。

**删除**：仅允许删除 `unassigned` 且无标注记录的图片（管理员）；已进入流程的只能归档文件夹，不删图片（可审计）。

### FR-04 领取任务（标注员）

工作台顶部两个入口：**按张领取** / **按文件夹领取**。

**A. 按张领取**

- 输入张数（默认 10，范围 1~100，上限可配置），可选「指定文件夹」下拉。
- 分配策略：`ORDER BY folder_id, seq`（先进先出，保持同文件夹连续），事务内 `SELECT ... FOR UPDATE SKIP LOCKED LIMIT N` 后批量 UPDATE。
- 返回实际领取数（池里不足时给「仅剩 X 张，已全部领取」）。
- 每人同时持有的未提交任务上限 `max_hold_per_user`（默认 100），超限拒绝并提示先完成；**按张与按文件夹两种领取方式都受该上限约束**（整包领取时只领到上限为止，剩余留在池里）。

**B. 按文件夹领取**

- 文件夹卡片上显示：总张数 / 剩余可领张数；剩余为 0 时置灰「已被领完」。
- 领取 = 该文件夹**当前全部 `unassigned`** 的图片；若已被他人领走一部分，弹二次确认：
  「文件夹《20261022》共 100 张，已被领取 23 张，本次将领取剩余 77 张」
- 事务内 `SELECT pg_advisory_xact_lock(folder_id)` 防并发重复发放。

**C. 领取后的约束（需求硬点）**

- 领取即写 `annotator_id`，公共池查询 `WHERE status='unassigned'`，**他人永远领不到**。
- 领取有效期 `lock_ttl_hours`（默认 24h）：到期未提交 → 后台任务回收为 `unassigned`，同时写审计日志 `claim_timeout`，并保留该用户的草稿（草稿私有，不外泄）。
- 标注员可「放弃」未提交任务（单张或整批），回到公共池。
- 管理员可对任意 `assigned/rejected` 图片「回收」或「改派」给指定标注员。
- 所有领取动作写 `claims` 表（模式、张数、文件夹），用于工作量统计。

**交互规格**

1. **打分**：每个维度一行「滑杆 + 数字框」，范围 0~20 且**只允许 0/5/10/15/20 五档**（滑杆自动吸附，数字框编辑时保留原输入，失焦或回车后才对齐（如 17 → 15），连续键入 15 不会被中途改为 5；留空表示未打分）；五维齐全才允许提交。键盘 `A/S/D/F/G` 依次跳到五个维度的分数框。
2. **总分**：实时计算并大字展示（五维相加，满分 100），附等级标签（优秀≥90 / 良好 80~89 / 中等 60~79 / 较差<60，阈值可配置）。
3. **点评（按维度写）**：五个维度各一个输入框——维度名在左、输入框在右，一行一维；每维 **10~50 字**，输入时实时显示「n 字 / 还差 N 字」，任一维不足 10 字或超过 50 字在提交时拦截并提示（并指出是哪个维度、还差几个字）。每个维度各有「常用评语」入口，把选中词条追加到**该维度**的点评里，词库由管理员维护。提交时后端把五维点评合成一条 `comment`（形如「白平衡：…；黑平衡：…」）供列表/导出展示，同时存 `dim_comments`（结构化五维点评）供导出与训练集使用。
4. **评估口诀帮助**：右上「查看示例」打开抽屉，内含《标注看图示例》四张示例图 + **五维口径表（白平衡/黑平衡/参差/结构/控笔 的解读 + 分值）**，标注员可随时对照，不离开当前任务。
5. **被打回任务**：进入时右侧顶部固定红色批注卡（审核员 + 时间 + 批注原文 + 快捷原因标签），历史批注全部列出；左侧图片可用批注坐标叠加显示（P1 图上圈注）。
6. **自动存草稿**：输入后 1s 防抖写 `drafts`（不改变图片状态），刷新/断网恢复；草稿按用户私有。
7. **提交**：`Ctrl/Cmd+Enter` 或按钮；提交成功 150ms 内自动切下一张（可关闭「提交后自动跳转」）。提交时带 `client_submit_id` 幂等，双击不会产生两条。
8. **切换保护**：有未提交改动时切上一张/下一张 → 二次确认「保存草稿并切换 / 放弃 / 取消」。
9. **图片加载**：先显示 thumb 占位，preview 加载完成淡入；预加载下一张 preview；加载失败显示「重新加载」并提供原图入口。
10. **键盘快捷键（全局，输入框聚焦时不触发分数键）**：

| 键 | 行为 |
| --- | --- |
| `Ctrl/Cmd + Enter` | 提交并下一张 |
| `←` / `→` 或 `[` / `]` | 上一张 / 下一张 |
| `A / S / D / F / G` | 跳到第 1~5 个维度的分数框（白平衡/黑平衡/参差/结构/控笔），键入数字直接生效 |
| `+` / `-` / `0`（配合 Ctrl） | 放大 / 缩小 / 适应窗口 |
| `E` | 打开「上报异常」面板 |
| `S` | 打开「常用评语」 |
| `?` | 快捷键帮助浮层 |

**异常上报面板（`E`）**

- 原因多选（来自配置，默认 6 项）：
  1. 图片倾斜超过 15°
  2. 严重失焦 / 笔画糊成一团
  3. 过曝 / 过暗，看不清笔画
  4. 含学生姓名、班级等未打码信息
  5. 手指 / 阴影 / 杂物遮挡文字
  6. 画面中无有效书写内容 / 重复图片
- 备注可选（≤200 字）。
- 异常任务**不需要**打分与点评，提交后 `kind=exception`。

### FR-06 我的任务（标注员）

Tab 页签 + 计数徽标：

| Tab | 内容 | 操作 |
| --- | --- | --- |
| 待完成 | `status=assigned`，按领取时间 | 继续标注 / 放弃 |
| 已驳回 | `status=rejected`，按最近驳回时间倒序，红色标记 | 看批注 → 重做 → 重新提交 |
| 待审核 | `status=submitted` | 只读查看 |
| 已通过 | `status=approved` / `excluded` | 只读查看 |

- 列表行：缩略图、文件名、文件夹、五维分/总分、状态、提交时间、驳回次数、最后批注摘要。
- 「已驳回」Tab 顶部常驻提示条：「你有 3 条被驳回，请按审核批注修改后重新提交」。

### FR-07 审核（审核员）

**审核队列**

- 默认 FIFO（`submitted_at` 升序），支持按文件夹、标注员、是否异常筛选。
- 队列进度：`本次队列 12/240`；支持「开始审核」进入逐条模式（左图 + 右标注 + 通过/打回）。
- 顶部信息：标注员、提交时间、第几次提交（version）、该标注员近期驳回率（辅助判断，不展示姓名以外的隐私）。
- **禁止审核自己标注的图**：队列自动过滤，接口二次校验。

**审核操作**

- 「通过」：一次点击即通过（可关闭「一键通过」，开启后需二次确认）。
- 「打回」：必须填写批注（≥5 字），可多选快捷原因标签：
  - 分数与点评不符
  - 某维度分数明显偏高 / 偏低（需勾选具体维度）
  - 点评太笼统，未指出具体问题
  - 未覆盖示例要求的维度
  - 异常判定不成立
  - 图片与点评内容不对应
  - 其他（自由填写）
- 可选「我要调整分数」：审核员在审核页直接改五维分数（只校验被改的维度，未改的保持原值），改分与总分一起写回标注记录，并写入 review 记录（含 `score_patch` 差异），标注员可见。**已实现**：改分区域常驻在审核页，未改动时可原样通过。
- 批注支持在图上画圈/箭头（P1；数据结构预留 `drawings` 字段：`[{type:"rect|arrow", x,y,w,h, color}]`，坐标为原图归一化坐标）。
- 审核动作全部写 `reviews` 表（一次审核一条，可多次打回，`review_count/reject_count` 挂图片冗余字段便于统计）。

### FR-08 统计看板

权限：管理员/审核员看全量；标注员只看自己。

**概览卡片**：总图片、待领取、进行中、待审核、已通过、已打回、无效图；今日上传 / 今日提交 / 今日审核 / 平均总分。

**标注员维度表**（可排序、可导出）：

| 列 | 定义 |
| --- | --- |
| 姓名 | — |
| 领取数 | claims 汇总（按张/文件夹） |
| 已提交 | 当前 version 的提交数 |
| 已通过 / 已打回 | 状态计数 |
| 驳回率 | 打回次数 / 已审核数（多次打回按次数计） |
| 一次通过率 | 首次提交即通过的图片占比（核心质量指标） |
| 平均总分 | 已通过图片总分均值 |
| 平均耗时 | `duration_ms` 均值（前端计时，从打开到提交） |
| 效率 | 张/小时（当日有效工作时长估算：提交时间跨度） |
| 异常上报数 | kind=exception 提交数 |

**文件夹维度表**：总张数、已领取、待审核、通过、打回、通过率、进度条。

**驳回分析**：按快捷原因标签 TOP N、按标注员分布、按维度（哪个维度最常被判"偏高/偏低"）、近 14 天驳回趋势折线。

**趋势图**：近 14 天「提交 / 通过 / 打回」三条线（recharts）。

**口径必须与库一致**：所有数字由 SQL 聚合得出，不做前端二次加工；接口返回的 `total` 必须与分页总数对账。

### FR-09 导出

入口：管理后台「导出」。

**筛选范围**

- 文件夹：全部 / 多选指定文件夹
- 日期区间：按图片创建日期（当天编号日期）或提交日期（可选字段）
- 标注员：全部 / 指定
- 状态：默认「仅已通过」；可选 已通过+无效图 / 全部（含待审核）
- 是否包含异常图（默认不包含）

**格式**

- `xlsx`（主格式，Excel 直接打开，含表头样式与列宽）
- `csv`（UTF-8 BOM，防 Excel 乱码）
- `json`（结构化，供下游训练/入库）
- `jsonl`（训练集，每行一条多模态样本，字段顺序 `messages → images`）：

```json
{"messages":[{"role":"user","content":"<image>请评价这位学员的硬笔楷书单字，并按五维给出评分与评语。"},
             {"role":"assistant","content":"白平衡（匀）：20/20\n黑平衡（稳）：20/20\n参差：15/20\n结构：20/20\n控笔：15/20\n总分：90/100\n档位：优秀\n总评：站得稳、居中；优先把捺再放长并写清捺角。"}],
 "images":["images/2/20261022_001.png"]}
```

  - 有效样本：`status=approved` 且五维齐全；无效样本：`status=excluded`，答案固定 `无效：<中文异常原因>，建议重拍`。
  - 未审核（submitted）与被打回（rejected）的图**不进**训练集。
  - `images` 路径约定 `images/<文件夹ID>/<服务器文件名>`，与导出的图片目录对应，可直接作为数据集根目录使用。

**xlsx 列（固定顺序）**

| 列 | 说明 |
| --- | --- |
| 文件夹 | 批次名，即用户要的"按文件夹名称" |
| 服务器文件名 | `20261022_001.png` |
| 原始文件名 | 上传时的原名 |
| 序号 | 当天序号 |
| 标注员 | 显示名 |
| 提交时间 | `YYYY-MM-DD HH:mm:ss` |
| 白平衡 / 黑平衡 / 参差 / 结构 / 控笔 | 各 0~20 |
| 总分 | 0~100（系统计算值） |
| 等级 | 优秀/良好/中等/较差 |
| 点评 | 原文 |
| 状态 | 已通过 / 无效图 |
| 审核员 | 显示名 |
| 审核时间 | — |
| 驳回次数 | 整数 |
| 异常原因 | 有则拼接，无则空 |
| 图片相对路径 | `20261022/20261022_001.png`（供归档核对） |

- 文件名：`font-label_<范围>_<yyyyMMdd_HHmm>.xlsx`
- 行数 ≤ 5000 同步流式下载；> 5000 转异步任务（`export_jobs`），完成后在「导出记录」下载，链接 24h 有效。
- 支持「同时打包图片 zip」（P1）：按文件夹分目录，文件名同服务器名。
- 导出动作写审计日志（谁、什么范围、多少行）。

### FR-10 审计与留痕

- 记录：登录/登出、上传、领取、放弃、提交、审核、改分、回收/改派、用户与配置变更、导出。

## 6. 评分规则（五维百分制，2026-10-22 口径更新）

> 原四维（撑满/布匀/挂稳/参差，各 10 分加权）已停用，历史标注保留旧快照。
> 现行为**五个维度，每维 20 分，总分直接相加 = 100 分制**。

### 6.1 五个维度（各 20 分，档位 0/5/10/15/20）

> 打分粒度固定为 5 分一档：**只能取 0 / 5 / 10 / 15 / 20**，滑杆按档调整，数字框在失焦或回车后才吸附到这些档位，
> 服务端也会校验（传 17 会被 422 拒绝）。

| 维度 | key | 解读（标注员看到的说明） |
| --- | --- | --- |
| 白平衡（匀） | `white` | 字/笔画与笔画之间的空白要均匀 |
| 黑平衡（稳） | `black` | 笔画长度代表重量；每个字从中间一分为二，两半的笔画总长度/重量大致相当 |
| 参差 | `variation` | 上下左右四面的笔画要有长有短，不能一样齐 |
| 结构 | `structure` | 分左右、上下、半包围、全包围、独体字，按结构逻辑看：哪边笔画多，哪边占位大；独体字参照「满」 |
| 控笔 | `control` | 笔画书写要有轻重变化（起收笔的粗细、顿挫） |

### 6.2 总分

`总分 = Σ(维度分)`，满分 100。五维等权（`weight=0.2`）时即为直接相加；若后台调整权重，按
`Σ(维度分 ÷ 满分 × 权重) ÷ Σ权重 × 100` 归一化。

- 系统**始终按当前方案计算并留快照**，不手填总分。
- 五个维度**必须全部打分**才允许提交（缺一维后端 422、前端禁用提交）。
- 每个维度只能取档位分（现行 5 分一档），非档位值后端 422。
- 每次提交写入 `rubric_snapshot`，之后改权重不会改写历史记录。

### 6.3 等级

优秀 ≥90，良好 80~89，中等 60~79，较差 <60（阈值可在评分方案里改）。

### 6.4 异常图

不打分、不点评，只选原因。审核成立后计入「无效图」，**不进入评分统计的平均分**，但计入标注员工作量与"异常发现"指标。
