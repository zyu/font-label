> 配套文档：`01-产品需求文档.md`（业务规则以此为准）
> 技术栈与现有 `piaowu/biz` 保持一致，降低团队切换成本。

## 1. 技术选型

| 配置 | env + `.env`（`godotenv` 仅开发） | 生产用环境变量/Compose |

## 3. 数据库设计

### 3.1 枚举取值

| 字段 | 取值 |
| --- | --- |
| `users.role` | `admin` / `reviewer` / `annotator` |
| `images.status` | `unassigned` / `assigned` / `submitted` / `approved` / `rejected` / `excluded` |
| `annotations.kind` | `score` / `exception` |
| `reviews.action` | `approve` / `reject` |
| `claims.mode` | `count` / `folder` |
| `export_jobs.status` | `pending` / `running` / `done` / `failed` |

维度键统一用英文，中文只在前端/配置里：`white`(白平衡) `black`(黑平衡) `variation`(参差) `structure`(结构) `control`(控笔)，每维 `max=20`、`weight=0.2`，总分即五维相加。

### 3.3 关键 SQL

**(1) 分配当日序号（原子）**

```sql
INSERT INTO daily_counters (day, last_seq)
VALUES ($1::date, 1)
ON CONFLICT (day) DO UPDATE SET last_seq = daily_counters.last_seq + 1
RETURNING last_seq;
```

多张图批量上传时，一次事务内循环取号即可（同事务串行，天然不重号；不同事务由行锁串行化）。

**(2) 按张领取（原子、无死锁）**

```sql
WITH picked AS (
    SELECT id FROM images
     WHERE status = 'unassigned'
       AND ($1::bigint IS NULL OR folder_id = $1)
     ORDER BY folder_id, seq
     LIMIT $2
     FOR UPDATE SKIP LOCKED
)
UPDATE images i
   SET status = 'assigned',
       annotator_id = $3,
       claimed_at = now(),
       lock_expires_at = now() + make_interval(hours => $4),
       updated_at = now()
  FROM picked p
 WHERE i.id = p.id
RETURNING i.id, i.folder_id, i.seq, i.stored_name, i.preview_path;
```

**(3) 按文件夹领取（防并发重复发放）**

```sql
SELECT pg_advisory_xact_lock($1::bigint);   -- folder_id
-- 再执行上面的 UPDATE，条件限定 folder_id 且 status='unassigned'
```

**(4) 提交标注（乐观并发 + 幂等）**

```sql
UPDATE images
   SET status = 'submitted', submitted_at = now(), updated_at = now()
 WHERE id = $1
   AND annotator_id = $2
   AND status IN ('assigned','rejected')
RETURNING id;
-- 影响 0 行 → 409 CONFLICT（任务已释放/已被审核/不属于你）
```

**(5) 审核（含禁止自审）**

```sql
UPDATE images
   SET status = CASE WHEN $3 = 'approve' AND $4 = 'exception' THEN 'excluded'
                     WHEN $3 = 'approve' THEN 'approved'
                     ELSE 'rejected' END,
       reviewed_at = now(),
       review_count = review_count + 1,
       reject_count = reject_count + CASE WHEN $3 = 'reject' THEN 1 ELSE 0 END,
       updated_at = now()
 WHERE id = $1 AND status = 'submitted' AND annotator_id <> $2
RETURNING id, status;
```

**(6) 超时回收（worker，每 5 分钟）**

```sql
UPDATE images
   SET status = 'unassigned', annotator_id = NULL, claimed_at = NULL,
       lock_expires_at = NULL, updated_at = now()
 WHERE status = 'assigned' AND lock_expires_at < now()
RETURNING id, annotator_id;
```
回收数量 > 0 时写 `audit_logs(action='claim.timeout')`，并更新对应 `claims.release_reason='timeout'`。

## 4. 接口契约（REST，`/api/v1`）

### 4.1 约定

- 鉴权：`Authorization: Bearer <access_token>`；Refresh 走 `POST /auth/refresh`（读取 httpOnly Cookie）。
- 成功：`200 {"data": ..., "request_id":"..."}`
- 失败：`4xx {"error":{"code":"FORBIDDEN","message":"...","fields":{"comment":"至少 5 个字"}},"request_id":"..."}`
- 分页：`?page=1&page_size=20`（`page_size` ≤100），响应 `{"data":{"items":[],"total":123,"page":1,"page_size":20}}`
- 时间：RFC3339（`2026-10-22T15:02:11+08:00`）
- 幂等：写接口接受 `Idempotency-Key` 头（提交标注必须带 `client_submit_id`）。

错误码：

| code | HTTP | 含义 |
| --- | --- | --- |
| `UNAUTHORIZED` | 401 | 未登录/token 失效 |
| `FORBIDDEN` | 403 | 角色不足 / 非本人任务 / 审核自己的图 |
| `NOT_FOUND` | 404 | 资源不存在 |
| `CONFLICT` | 409 | 状态不允许（已被领取/已提交/重复文件名/重名文件夹） |
| `VALIDATION_FAILED` | 422 | 字段校验失败（含 `fields`） |
| `LIMIT_EXCEEDED` | 429 | 持有任务超上限 / 领取过于频繁 |
| `INTERNAL` | 500 | 服务端错误（不泄漏细节，带 request_id） |

服务端校验：`kind=score` 时五个维度必须齐全、0~20 且落在步长档位上（现行 `step=5`：只能 0/5/10/15/20）；**五维点评必须齐全**，每维字数在 `[dim_comment_min, dim_comment_max]`（现行 10~50 字），缺哪维/差几个字都写进 `fields.dim_comments`；`kind=exception` 时原因 ≥1 项且属于配置枚举。总分/等级由后端按当前 rubric 计算，**忽略前端传的 total**。`comment` 由后端用五维点评合成（`白平衡：…；黑平衡：…`），前端不再单独传。

- `POST /api/v1/exports` 的 csv/xlsx 每个维度占两列：`<维度名>` 与 `<维度名>点评`（如 `白平衡（匀）`、`白平衡（匀）点评`）。

- `POST /api/v1/exports`，请求 `format=jsonl`，返回训练集 ZIP（`application/zip`）：单个 `data.jsonl`（N 行）与 `images/`（N 张原图），文件名为 `<图片ID>_<服务器文件名>`，JSONL 路径与 ZIP 内路径一致且全局唯一。每行字段顺序固定 `messages → images`；assistant 内容形如
  `白平衡（匀）：20/20；点评：<该维点评>\n…总分：90/100\n档位：优秀`；无效图为 `无效：<原因>，建议重拍`。
  仅输出 `status=approved`（且五维齐全）与 `status=excluded` 的图，其余行跳过（避免未审核数据进训练集）。
  所有导出写入 `export_jobs`，即时下载也保存文件、状态、实际行数及过期时间；超过 5000 条排队由 worker 打包，图片流式写 ZIP，缺图报错。`GET /exports` 列出所有导出，`GET /exports/{id}/download` 可在 24 小时内再次下载。

## 5. 图片存储与访问

### 5.1 目录与变体

```
storage/
  20261022/
    20261022_001.png            # original（最长边 ≤2400，超限降采样）
    .derived/20261022_001.preview.webp
    .derived/20261022_001.thumb.webp
```
`rel_path` 存相对路径，DB 不存绝对路径（换机器/挂载不炸）。

### 5.2 签名 URL

`sig = base64url(HMAC-SHA256(secret, image_id|variant|exp))`
`GET /api/v1/media/101/preview?exp=1761200000&sig=...`
校验：`exp > now` 且 `hmac.Equal`。好处：`<img src>` 可直接用，不需要带 Authorization 头，不暴露可猜测路径，5 分钟后链接失效。

### 5.3 上传流水线

1. 校验扩展名/MIME/魔数（`http.DetectContentType` 前 512B）。
2. 读入临时文件，计算 sha256（流式，不整读进内存）。
3. `begin` 事务 → 取 `daily_counters` 序号 → 计算 `stored_name`。
4. bimg 读图：`AutoRotate` → 若最长边 >2400 则 `Thumbnail` 等比缩小 → 输出原格式（heic→jpeg）。
5. 写 `storage/<folder>/<stored_name>`，生成 preview(1280 webp q82)、thumb(320 webp q80)。
6. `INSERT images`（`ON CONFLICT (folder_id, sha256) DO NOTHING` → 命中即判定重复）。
7. 事务提交；提交后若为重复则删除刚才落盘的文件（避免垃圾文件）。
8. 审计日志 `image.upload`。

失败回滚：每一步失败都要清理临时文件与已写入的目标文件（defer + 标记）。

## 6. 后端实现要点

### 6.1 中间件顺序

`requestID → recover → accessLog(slog) → CORS(仅开发) → auth(JWT) → requireRole → handler`

JWT claims：`{sub, role, tv(token_version), exp, iat}`。校验时比对 `users.token_version`（Redis 缓存 60s 可选，首版直接查库，QPS 不高）。

### 6.2 事务助手

```go
func (d *DB) Tx(ctx context.Context, fn func(pgx.Tx) error) error
```
所有跨表写（领取、提交、审核、上传）必须在单一事务内完成。

### 6.3 总分计算（唯一真源）

```go
type Dim struct{ Key, Label string; Weight float64; Max int }
func CalcTotal(scores map[string]int, dims []Dim) (float64, string) // 返回值与等级
```
前端**同样实现一份仅用于实时预览**，后端为准；提交响应里回传 `total/grade`，前端覆盖显示。

### 6.4 定时任务（worker 进程）

| 任务 | 频率 | 内容 |
| --- | --- | --- |
| 超时回收 | 5 min | `assigned AND lock_expires_at < now()` → `unassigned` |
| 异步导出 | 30 s 轮询 | `export_jobs.status='pending'` → 生成文件 |
| 过期清理 | 1 h | 删除 >24h 的导出文件、>30d 的 `drafts` 孤儿（图片已提交且草稿无变更） |
| 备份触发 | 每日 03:00 | 调 `pg_dump`（可交给 crontab/运维） |

单机部署可用 goroutine + ticker；多实例需换 `FOR UPDATE SKIP LOCKED` 抢占任务（表里加 `locked_until`）。

### 6.5 权限校验点（不能只在路由层）

| 场景 | 校验 |
| --- | --- |
| 看/提交某图 | `images.annotator_id == ctx.User.ID` |
| 审核某图 | `images.annotator_id != ctx.User.ID` 且角色 ∈ {reviewer, admin} |
| annotator 查列表 | SQL 层强制 `annotator_id = $self`（不信任前端传参） |
| 导出 | 仅 admin（可选 reviewer） |
| 图片签名 | exp + HMAC，与用户身份无关（短时有效） |

## 7. 前端实现要点

### 7.1 状态划分

- **服务端状态**：react-query（`queryKey: ['claim','my',status]`），提交后 `invalidateQueries(['claim','my'])` + `setQueryData` 乐观更新队列。
- **页面状态**：zustand 单 store：
  ```ts
  type WorkbenchStore = {
    queue: number[];          // 本次领取的图片 id 序列
    cursor: number;           // 当前位置
    viewer: {scale:number; x:number; y:number};
    dirty: boolean;
    setQueue(ids:number[]): void;
    next(): void; prev(): void;
    ...
  }
  ```
- **⚠ 已知坑（必读）**：Zustand v5 中若在 undo/快照逻辑里连写两次 `set()`，会因浅比较合并导致视图不更新。本项目的规则：**一次状态变更只调用一次 `set()`**，用函数式更新返回完整新状态。

### 7.2 图片查看器

- 容器相对定位 + `transform: translate(x,y) scale(s)`，`transform-origin: center`。
- 滚轮缩放以鼠标点为锚：`newX = mx - (mx - x) * (s2/s1)`。
- 拖拽平移用 pointer events；`touch-action: none`。
- 上下限：`scale ∈ [0.2, 8]`；双击在 1x / 2x 切换。
- 「适应窗口」= 计算 `min(containerW/imgW, containerH/imgH)`。
- 叠加层（P1 批注）用绝对定位 div + 归一化坐标换算，避免 canvas 重绘复杂度。

### 7.3 性能

- 领取后只请求当前图详情，其余只拿列表项（含 thumb URL）。
- 预加载：`cursor+1` 的 preview 用 `new Image().src`。
- 列表虚拟滚动（`@tanstack/react-virtual`）当一次 >100 项时启用。
- Vite 生产构建按路由 code-split，标注页单独 chunk。

### 7.4 交互防错

- 切换图片前检查 `dirty`，弹确认（AntD `Modal.confirm`）。
- 提交按钮 loading + disabled，避免双提交。
- 网络失败保留表单内容，提示「重试」，不清空。
- 快捷键在 `input/textarea` 聚焦时只放行 `Ctrl+Enter`。

  worker:
    build: ../server
    command: ["/app/worker"]
    env_file: .env

    image: nginx:alpine

## 10. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 并发领取重复发放 | 数据错误、信任崩塌 | `FOR UPDATE SKIP LOCKED` + 文件夹 advisory lock；上线前用 50 并发脚本验证（见验收 A-05） |
| 序号并发重号 | 文件名冲突 | 单行 `daily_counters` 行锁，同事务内取号 |
| 大图拖垮浏览器/带宽 | 标注卡顿 | 三档图 + 原图按需；preview ≤300KB |
| 手机照片方向错乱 | 无法评分 | 上传时 `AutoRotate` 并按 Orientation 转正 |
| 评分口径不一致 | 数据不可用 | rubric 可配置 + 快照 + 审核改分统计；首月专项校准会 |
| 领取囤积不干活 | 任务卡死 | 持有上限 + 24h 超时回收 + 管理员改派 |
| 图片被外部遍历 | 隐私泄漏 | 签名 URL + 5 分钟过期 + 禁用目录索引 |
| libvips 依赖 | 构建失败 | Dockerfile 装 `vips-dev`；预留 imaging 降级开关 |
