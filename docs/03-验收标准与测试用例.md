# 验收标准与测试用例

> 用途：开发自测 + 甲方验收。每条都能"照着点一遍"出结论。
> 约定：`管理员=A`、`标注员1=B`、`标注员2=C`、`审核员=D`（D 不是 B/C）。

## 0. 验收通过线（Definition of Done）

一个功能算"做完了"，必须同时满足：

1. 本文档对应用例全部通过（含反向用例）。
2. 页面有 loading / 空态 / 错误态，不是白屏。
3. 权限用例通过（越权一律 403，不能"前端藏起来、接口能调"）。
4. 所有状态变更在 `audit_logs` 里查得到。
5. 后端有单元测试覆盖总分计算、状态机、领取原子性；前端有至少 1 个组件测试（打分面板）。

## 1. 功能用例

### 1.1 上传与命名

**A-01 命名规则**
- 前置：系统日期 2026-10-22，文件夹不存在。
- 步骤：A 上传 `IMG_0231.jpg`，文件夹留空。
- 预期：
  - 自动创建文件夹 `20261022`；
  - 落盘 `storage/20261022/20261022_001.jpg`；
  - DB `images.stored_name=20261022_001.jpg`，`orig_name=IMG_0231.jpg`，`day=2026-10-22`，`seq=1`；
  - 状态 `unassigned`。

**A-02 序号递增与跨文件夹**
- 步骤：同日再上传 3 张到 `20261022`，再新建文件夹 `三年级二班` 上传 2 张。
- 预期：序号连续为 `002,003,004`，然后 `005,006`；`stored_name` 全局唯一。

**A-03 扩展名统一小写**
- 步骤：上传 `A.PNG`、`b.JpG`。
- 预期：落盘 `..._007.png`、`..._008.jpg`（扩展名小写），`mime` 正确。

**A-04 重复图片**
- 步骤：把已上传的同一张图再拖进同一文件夹。
- 预期：该条返回 `DUPLICATE`，提示"已存在同图 20261022_007"，磁盘不新增文件，DB 不新增行。

**A-05 非图片 / 超大文件**
- 步骤：上传 `a.pdf`、30MB 的 jpg。
- 预期：分别返回 `UNSUPPORTED_TYPE`、`FILE_TOO_LARGE`，其余合法文件仍成功（不整批失败）。

**A-06 手机照片方向**
- 步骤：上传一张 EXIF Orientation=6 的竖拍照片。
- 预期：缩略图与标注页中内容正立，不侧躺；DB `width/height` 是转正后的值；导出不含 EXIF（`exiftool` 检查无 GPS）。

**A-07 并发上传不重号**
- 步骤：两个管理员会话同时各上传 20 张（用脚本并发，见 §3）。
- 预期：共 40 张，`stored_name` 无重复，`seq` 集合恰为 1..40，无 500。

**A-08 拖拽整个文件夹**
- 步骤：拖入本地目录 `三年级二班`（含 12 张图）。
- 预期：自动创建同名文件夹并全部入该文件夹。

### 1.2 领取

**A-09 按张领取**
- 前置：池中有 100 张未领取。
- 步骤：B 输入 10 领取。
- 预期：`granted=10`；这 10 张 `status=assigned, annotator_id=B`；工作台「待完成」显示 10；`claims` 新增一条 `mode=count, granted=10`。

**A-10 按文件夹领取**
- 前置：文件夹 `20261022` 共 30 张，全部未领取。
- 步骤：B 点该文件夹「领取」。
- 预期：30 张全部归 B，提示"已领取 30 张"。

**A-11 按文件夹领取（部分被领）**
- 前置：同上，C 已领走 8 张。
- 步骤：B 领取该文件夹。
- 预期：弹确认「共 30 张，已被领取 8 张，本次将领取 22 张」；确认后 B 得 22 张，确认框取消则 0 张。

**A-12 领取后不可重复领取（核心）**
- 前置：A-09 后 B 持有 10 张。
- 步骤：C 刷新工作台可见列表、并直接调 `POST /claims` 连续领取 30 张。
- 预期：C 拿到的任何一张都不属于 B 领取的 10 张；库里不存在同一 image 有两名 annotator 的情况（§3 对账 SQL 返回 0 行）。

**A-13 并发领取同一张**
- 步骤：脚本让 B、C 同时各领 5 张（池中仅剩 5 张）。
- 预期：合计 granted = 5；无重复 id，无报错；先到者全拿或按剩余切分均可，但**绝不能重复**。

**A-14 持有上限**
- 前置：`max_hold_per_user=100`，B 已持有 100 张未提交。
- 步骤：B 再领 1 张。
- 预期：`429 LIMIT_EXCEEDED`，提示"请先完成或放弃已有任务"。

**A-15 放弃任务**
- 步骤：B 放弃其中 3 张。
- 预期：这 3 张回到 `unassigned`，C 能领到；`claims.release_reason='manual'`；审计有记录。

**A-16 超时回收**
- 步骤：改 `lock_ttl_hours=0.01`（或直接改库里 `lock_expires_at = now()-1h`），等 worker 跑一轮。
- 预期：过期任务变 `unassigned`，`annotator_id` 清空；B 的草稿仍在（他人看不到）；审计 `claim.timeout`。

**A-17 管理员改派**
- 步骤：A 把 B 的某张 `rejected` 图改派给 C。
- 预期：C 的「我的驳回」出现该图，并能看到历史审核批注；B 列表消失。

## 3. 对账与并发脚本

**重复持有对账（应恒为 0 行）**

```sql
-- 一张图不可能有两个持有人：annotator_id 只有一个字段，这里对账"领取记录与实际归属是否错位"
SELECT i.id, i.annotator_id, c.user_id
  FROM images i
  JOIN claims c ON i.id = ANY(c.image_ids)
 WHERE i.annotator_id IS DISTINCT FROM c.user_id
   AND c.released_at IS NULL
   AND i.status IN ('assigned','submitted','rejected');
```

**状态与数据一致性**

```sql
-- 1) assigned 必须有持有人与过期时间
SELECT count(*) FROM images WHERE status='assigned'
   AND (annotator_id IS NULL OR lock_expires_at IS NULL);        -- 期望 0

-- 2) unassigned 不得残留持有人
SELECT count(*) FROM images WHERE status='unassigned'
   AND (annotator_id IS NOT NULL OR claimed_at IS NOT NULL);     -- 期望 0

-- 3) submitted/approved/rejected/excluded 必须有标注
SELECT count(*) FROM images i LEFT JOIN annotations a ON a.image_id=i.id
 WHERE i.status IN ('submitted','approved','rejected','excluded') AND a.id IS NULL; -- 期望 0

-- 4) approved 的分数型标注必须有四维分与点评
SELECT count(*) FROM images i JOIN annotations a ON a.image_id=i.id
 WHERE i.status='approved' AND a.kind='score'
   AND (a.scores IS NULL OR a.comment = '');                      -- 期望 0

-- 5) 审核记录数 = images.review_count
SELECT count(*) FROM images i
 WHERE i.review_count <> (SELECT count(*) FROM reviews r WHERE r.image_id=i.id); -- 期望 0
```
